# Projection: from `cdop.*` tables to CDOP documents

The database is normalised: one table per concept, one row per status change, no parallel arrays, real geometry. CDOP documents are denormalised views of that data. `apps/api/src/domain/projection/cdop.ts` loads a `ProjectAggregate` (batched per-table queries) and produces the Full List document and each per-pod slice with pure functions. Ajv validates every document at seed time and in CI.

This page lists which table feeds which section, the three defect workarounds, and the value projections. Field ids are the schema's `x-cdop-field-id` values.

## The three defect workarounds

1. **`project."crediting period"` is never emitted** (`CDOP-FB-002`). The duration of the current period is available as `duration_years` on the API's crediting-period data, and the period's dates are in `validation.validation[]`.
2. **`unit.credit_blockblock_start` is emitted beside `credit_block[]`** (`CDOP-FB-003`). Full List requires the mangled key, so the API sets it to the block's `block_start` while also emitting `credit_block[].block_start`, `block_end` and `quantity`. Unit Description gets only the clean array.
3. **`unit` and `vintage` appear only in per-unit documents** (`CDOP-FB-005`). The project-level Full List omits them unless `?unit_id=` is given; `/v2/units/{id}/cdop/full-list` and `/v2/units/{id}/cdop/unit-description` carry them.

## Absent sections and strict mode

By default a section with no data is omitted. The document is then honest but may fail the upstream `required` list (`agreement`, `cobenefits`, `estimations`, `geolocation_file` and `compliance_market_id` are all required by Full List).

`?strict=1` switches on placeholders. Where the schema allows an empty-but-valid value (an empty array, an object with only its required scalars), the API emits it. Each placeholder is listed in the `X-CDOP-Conformance` response header with the register entry that explains it. Where no valid placeholder exists (`compliance_market_id` with `minItems: 1`), the header names the field and the document stays invalid.

## Value projections

| Value                                          | Rule                                                                                                                                                                                                                              |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `project.status[].project_status`              | From the native state row (`native_state.cdop_project_status`), which is the registry's own code mapped once.                                                                                                                     |
| `unit.status[].status`                         | `cdopUnitStatus(state, state_reason)`: pending and active → Active; on_hold → Pending Transfer, Accepted Pending Payment or On Hold by reason; buffer → Deposited Released; retired → Retired; cancelled and expired → Cancelled. |
| `unit.descriptor[].type`                       | The registry's unit type verbatim (`PIU`, `VCU`, and also `WCU`/`PCU`, which the enum lacks; `CDOP-FB-025`).                                                                                                                      |
| Integer ids (`validation_id`, `estimation_id`) | The record's per-project `sequence`.                                                                                                                                                                                              |
| `project_risk`                                 | `JSON.stringify` of the stored object.                                                                                                                                                                                            |
| Dates                                          | `*_on` columns as `YYYY-MM-DD`; timestamps as RFC 3339 UTC.                                                                                                                                                                       |
| Enum strings                                   | Exactly the vendored strings, including known typos.                                                                                                                                                                              |

## Verifying the projection

```bash
pnpm seed
pnpm test                                   # conformance: every seeded project × every pod through Ajv
curl -s http://localhost:3000/v2/projects/<id>/cdop/full-list?strict=1 -D - -o /dev/null | grep -i x-cdop
```
